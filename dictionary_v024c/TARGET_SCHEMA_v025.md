# Словарь v0.25: смыслы, варианты определений, подсказки и сложность

**Статус:** целевая спецификация, не опубликована в игре. Рабочий v0.24d оставлен без изменений.
**Требование владельца, 25.10.2026:** слово может иметь несколько разных определений для тематических кроссвордов; одно и то же определение может использоваться как основной вопрос либо дополнительная подсказка. Сложность должна определяться **для каждого определения**, а также учитываться при сборке целого кроссворда.

## 1. Модель данных

- **Word**: уникальная русская лемма (основная форма), число букв, часть речи, грамматическая проверка, общие параметры слова и статус редакторского утверждения.
- **Sense**: отдельное лексическое значение (например, «ЖУРАВЛЬ» как птица и как рычаг колодца). Позволяет не смешивать омонимичные и переносные значения.
- **Clue**: независимое, самодостаточное определение конкретного смысла. У каждого свои `id`, `text`, `topic_ids`, `difficulty`, `style`, `status`, `source_refs`, `can_be_primary` и `can_be_hint`. Одно слово — много таких записей; снятие лимита в 3 варианта предусматривается в новой версии.
- **Hint**: может быть выбран из других допустимых clues этого слова либо быть специальным поэтапным текстом; связь с основным определением хранится как ссылка на ID. Для специальных подсказок — уровни раскрытия. Не давать подсказку, которая просто повторяет вопрос.
- **Topic**: тематическая категория задаётся прежде всего на уровне **clue**, не только на уровне слова. Категории одного слова — объединение тематик определений или отдельные общие семантические теги.
- **Difficulty**: сложность конкретной формулировки и необходимого знания, НЕ просто длина слова; уровень 1–5 с оценкой уверенности и редакторским подтверждением. Отдельно можно хранить `lexical_difficulty` слова и рассчитывать `puzzle_difficulty` при генерации сетки.
- **Usage**: факт включения clue в кроссворд хранится отдельно в записи задания (clue ID, hint IDs, theme, requested difficulty), а не мутирует сам словарь.

## 3. Шкала сложности отдельного определения

1. **Очень легко**: узнаваемое, буквально описанное понятие; для лёгких вводных сеток.
2. **Легко**: известная пословица, популярный устойчивый оборот.
3. **Средне**: школьный культурный/литературный/исторический факт; требуется ассоциация.
4. **Сложно**: более специализированный исторический, научный, художественный факт.
5. **Очень сложно**: редкое, но проверенное знание; только после экспертного контроля однозначности.

Оценка зависит от **знания, косвенности, частотности культурной отсылки, неоднозначности и формулировки**. Не снижать сложность только из-за длины ответа, не повышать автоматически из-за длинного текста. Правильность факта и уникальность ответа проверяются отдельно и не маскируются уровнем сложности.

## 4. Автоматическое определение + ручная редактура

1. Черновая оценка `difficulty.level` (1–5) по содержимому clue с пояснением `reason` и статусом `estimated`.
2. Редактор может принять/исправить уровень — сохранять `status: owner_confirmed`. Присвоенный пользователем вариант текста сам по себе **не означает подтверждение его сложности**.
3. Без оценки не подменять `null` словесным `easy`; учитывать `unrated` и исключать из режима «точная сложность» до проверки.
4. После игр корректировать сложность статистически: доля разгадок без подсказок, время разгадывания, число использованных подсказок. Собирать только необходимые, по возможности агрегированные данные и не изменять экспертный уровень без контроля.
5. Общую сложность **кроссворда** считать отдельно по сложности выбранных определений, частотности слов, длине, количеству пересечений, стартовым буквам и подсказкам.

## 5. Выбор для тематического кроссворда

- Подбирать варианты по `clue.topic_ids`, а не только `word.topical_categories`.
- Например, «Литература» → ЖУРАВЛЬ/gamzatov; «Геральдика» → ЖУРАВЛЬ/heraldry; «Пословицы» → ЖУРАВЛЬ/folk_wisdom.
- При повторе слова в разных тематических выпусках разрешать другой clue; **в одной сетке слово не дублировать**, если это не специальный режим.
- Основное определение задаётся конкретной выбранной записью `clue.id`, дополнительная подсказка — другим clue.id либо отдельным `hint.id`.
- Слишком близкие или несоответствующие подсказки должны исключаться редакционной проверкой.

## 6. Совместимость и миграция

Текущий v0.24d хранит категории в `topical_categories` **на уровне слова**, глобальный `difficulty: "easy"` и несколько `senses[0].clue_variants` без собственных категорий/сложности; `senses[0].hint` — один текст. Это недостаточно для точной тематической и рейтинговой генерации.

Для v0.25 нужна **добавочная миграция**, сохраняющая исходные словарь и owner overrides без потери текста:
- каждому старому `clue_variant` присвоить отдельную запись clue с тем же ID, текстом и метками редакторского статуса;
- скопировать категории слова только как **временные наследуемые** теги (`topics_pending_review`); не считать их проверенными категориями каждого clue;
- сложности поставить `null / estimated` до отдельной оценки, не наследовать общее `easy` без оснований;
- текущие `hint` сохранить как самостоятельные объекты и установить связи с clue только после проверки;
- отдельно выделить разные смыслы и двусмысленные культурные отсылки;
- поддерживать совместимое представление для нынешнего редактора/генератора, пока новая схема не проверена;
- никакого изменения live-игры, публикации и присвоения `approved` без согласия владельца.

**Мобильный UX:** вопросы должны укладываться в 2 строки крупного шрифта на небольшом Android; предварительная планка — 70 знаков, реальная проверка обязательна.
