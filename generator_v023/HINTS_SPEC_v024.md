# Добрые Кроссворды — дополнительные смысловые подсказки (v0.24 → v0.25)

## Задача

Дать игроку возможность получить **одну дополнительную смысловую подсказку** для выбранного слова, не раскрывая букв и не показывая ответ.

**Подсказка** может быть:
1. `synonym` — один хорошо известный, точный синоним ответа;
2. `alternate_meaning` — **другое самостоятельное значение того же слова**.

Подсказка не обязана быть у каждого слова: лучше честно оставить её отсутствующей, чем добавлять неточный синоним или искусственную формулировку.

## Пример пользователя

- Ответ: **КЛЮЧ**.
- Основное определение: **Знак нотной записи, который ставят в начале нотного стана.**
- Дополнительная подсказка (другое значение): **Им также открывают дверной замок.**

Важно: `КЛЮЧ` здесь только иллюстрация требования — автоматически создавать его в текущих девяти сетках не нужно.

## Формат данных

Отдельное *необязательное* поле `hint` в записи размещения слова:

```json
{
  "word": "КЛЮЧ",
  "clue": "Знак нотной записи, который ставят в начале нотного стана.",
  "hint": {
    "kind": "alternate_meaning",
    "text": "Им также открывают дверной замок."
  }
}
```

В одном слове — **максимум одно** поле `hint`, не массив. Слова без качественной подсказки не получают поле.

## Редакторские правила

- Подсказка должна точно относиться к ответу, а не к пересекающемуся слову.
- `synonym` — не просто ассоциация, гипероним или частичный аналог. Если синоним меняет значение, не использовать.
- `alternate_meaning` — действительно другое, хорошо известное значение того же слова. Вторая формулировка должна не повторять основное определение.
- Дополнительная подсказка не должна **содержать написанный ответ** в любом регистре, даже внутри длинной фразы.
- Не добавлять вторую подсказку, последовательность уровней, буквы или автоматическое раскрытие ответа.
- Проверять грамматику, отсутствие недопустимых слов, понятность для пожилых людей.
- Полная лингвистическая корректность и точность синонимов требуют редакторской проверки; автоматический тест ловит лишь формат и буквальное раскрытие ответа.

## UX для игрового режима v0.25

- При выборе слова показать одну кнопку **«💡 Подсказка»**, если дополнительная подсказка для него подготовлена.
- По первому нажатию вывести отдельный текст под основным определением; **не подменять** основное определение.
- Сохранять открытое состояние подсказки в текущей партии, чтобы не заставлять игрока нажимать снова.
- Не показывать ответ и не заполнять клетки.
- Кнопки крупные, хороший контраст, подсказка доступна и с TalkBack; не использовать таймер.
- Никаких штрафов или рекламы за такую смысловую подсказку в первом доступном для проверки варианте.
- Когда поле `hint` отсутствует, не показывать неработающую кнопку.

## Реализация на текущем этапе

В `filled_ornaments_v023b.json` внесены **10 уникальных слов** с тщательно выбранными предварительными формулировками (11 появлений в девяти кроссвордах, так как БАЗА встречается дважды). Это редакторские черновики, не подтверждённые для релиза. Кнопка в существующем предпросмотре пока не включена: она появится вместе с полноценным вводом букв в игровом v0.25.

Перед релизом провести редакторскую проверку и, по возможности, обеспечить подсказками все слова, для которых существует **качественный** синоним либо другое значение.
